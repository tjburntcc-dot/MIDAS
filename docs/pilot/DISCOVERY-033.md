## Public-reader compatibility repair

The initial real public read exposed a Node 24 transport defect: with DNS lookup option `all:true`, the socket requires an array of address/family objects. The old pinned callback returned the scalar shape. `createPinnedLookup` now returns the correct shape while keeping exactly the one previously vetted address; it does not perform another DNS lookup. This matches the official [Node DNS lookup contract](https://nodejs.org/api/dns.html#dnslookuphostname-options-callback) and [socket connection options](https://nodejs.org/api/net.html#socketconnectoptions-connectlistener).

A restricted-shell attempt then returned Windows `EACCES`. Under separately approved public-network permission, a single bounded GET of `https://fitkitty.com/robots.txt` returned HTTP 200 and 3,616 bytes. Evidence is retained in `var/discovery-public-diagnostic/fitkitty-robots-approved-network.json`. The original failed observations remain unchanged. This demonstrates the repaired public HTTP transport only; no provider inference, token count, credential access or model judgment occurred.
