## Launch and owner journey

From the Mission 029 worktree:

```powershell
node packages/foundry/src/workbench/server.ts --root var/integrated-workbench-029 --port 43129
```

Open http://127.0.0.1:43129. Choose Support or Supplier invoices (three related eight-invoice batches), then Create workspace. Analyze evidence (explicit mock), inspect source references, Accept as provisional interpretation, Create pinned work plan, Run/resume, inspect the preserved original and corrected artifact, check the exact approval box and Approve/continue. The final view shows authenticated fixture outcome and persistent business feedback. Refresh or restart using the same root to recover state. Do not run multiple servers on one root.

Every provider path is disabled here. Source edits are retained and analyzable, but execution refuses an edited corpus until an adapter explicitly supports it; it never executes silently on old evidence. Fixed fixture proposals are clearly labeled, not presented as responsive real-model reasoning. Arbitrary businesses, real evidence connectors, actual business actions and general team optimization remain unimplemented.

The server binds loopback only. Mutations require the local browser session, exact origin and CSRF token. This is a single-owner local application, not a multi-user security boundary. Ordinary approval uses readable register/memo, exact hash and effect limit; JSON is optional provenance detail. UI automation approvals are synthetic test interactions, not founder review.
