## Failure and recovery behavior

The scheduler admits every model/tool step separately. Model and tool counters are attributed by task and venture. Uncertain steps retain their reservation; local scheduling counters never become a provider invoice or business cost.

| Trigger | Persisted response | Verified boundary |
| --- | --- | --- |
| Two workers claim the same task | One lease/generation wins; other claim returns no assignment. | Real process contention test; version-checked SQLite transaction. |
| Lease expires without an admitted step | Recover the existing task checkpoint under a new fenced generation. | Old token cannot heartbeat or complete the task. |
| Heartbeats continue without progress | Separate progress time permits stalled-work diagnosis. | A live PID/heartbeat is not sufficient evidence of progress. |
| Model result is received but invalid | Preserve the returned result; consume the known call; block on contract failure. | No successful artifact or semantic result is inferred from the invalid response. |
| Model admission has no durable result | `needs_reconciliation`; retain exposure. | Recovery performs no new inference. The missing response is not guessed. |
| Process stops after durable model/tool response | Verify exact task/step/request/output hashes and reconcile the original admission. | Reuse the original response and execution index, with no duplicate model request. |
| Local edit commits before engine result persistence | Recover the completed trusted local operation by its pinned identity, then preserve/reconcile its result. | Service interruption test retains exactly one source edit and six model decisions. |
| Pause/cancel during admitted work | Stop new admission; retain output/effect evidence and uncertainty. | Unpublished output is retained; cancellation cannot erase unresolved effects. |
| Artifact/source changes | Stale pending work and consumers; preserve previous versions. | Old approval/input bindings cannot make changed output current. |
| Missing workspace/check contract | Visible capability block before a model call. | A capability name alone cannot count as fulfilled work. |
| Model says “complete” without checked current delivery | Block completion. | Engine requires trusted current checks and authenticated local delivery readback. |

Recovery tests reopen the database and construct a new engine after simulated process death at explicit persisted boundaries. The contention test uses separate actual child processes. These are complementary tests; the simulated engine interruption is not represented as a full operating-system crash campaign.

## Remaining substantive limits

1. **General business discovery and execution remain bounded.** The executive produces finite schema-checked plans over registered capabilities. It cannot invent and install a new trusted job checker, deploy arbitrary software, create accounts, or execute an unknown business model by labeling a task. The model planner creates at most 12 new tasks per proposal; their dependencies refer to earlier tasks in that proposal. Automatic cross-venture artifact sharing and learned team/resource optimization are not demonstrated.

2. **Evidence refresh remains a controlled task operation.** The audit found and the integration corrected a gap between retrieval and the frozen report input contract. `LocalWorkTools.updateInputs()` now versions controller-supplied source updates, preserves every existing source ID and required source obligation, pins packet metadata, and invalidates current verification. A refreshed URL may change source text under a new preserved input revision; this does not silently revise old packets or establish source truth. External source changes stale affected execution before its next action. The worker cannot use a tool call to rewrite its own acceptance contract. The new preparation test covers fetch → input revision → current quotation → checks → local delivery; real network behavior and actual-model research quality remain separate evidence requirements.

3. **Research context has a finite admission boundary.** Worker context has a 56 KB bound. Current integration includes source metadata and explicitly marked previews (up to 2 KB per source and a shared preview budget), four recent tool observations, and the latest requested file/source read. Local `research.read` exposes preserved source chunks up to 12,000 characters without another search; older reads remain identified and can be requested again. It remains available to review tasks without enabling search or fetch. A planning task receives complete authoritative service reports up to an 18 KB shared report bound, then visibly blocks on excess. This reduces duplication but is not learned evidence selection or a demonstrated strategy for every long document. Full source reading still consumes finite task steps. Search and public retrieval require their connected ports and their own authority. A connector implementation or fixture response is not evidence of a live research run.

4. **Acceptance is profile-specific.** Proposed textual acceptance conditions supplement fixed trusted check profiles. They do not automatically create independent semantic tests for arbitrary commercial or engineering claims. Source quotation proves provenance, not truth or causality. Supported output must still earn owner/customer acceptance.

5. **Learning has no demonstrated specialist win.** Registry tests prove scope, comparison, adoption, pinning, and rollback mechanics. No fresh actual-model comparison in this record establishes superior software, research, service, or sales performance. Generated tasks without explicit procedure-scope/baseline metadata use the excellent generic baseline. Existing executions retain their pinned procedure after adoption or rollback; they are not silently rewritten.

6. **Commercial and financial outcomes remain unobserved.** Local delivery/download is implemented. External acquisition, sending, customer reply handling across this new portfolio, delivery acceptance, activation, revenue, cancellation, and actual operating economics are not established by these tests. Research/build/commit task lanes do not themselves grant commercial authority. The preserved v1 communication/grant machinery is separate.

7. **Continuity is local.** SQLite coordination, process leases, tool recovery, and tested backup/restore support local continuity. Cross-host shared state, remote authentication, supervision and cost controls need a concrete deployment and verified recovery under their actual authorization before unattended remote operation can be claimed.
